# UI 스펙 — Windows IME 상태 인디케이터

`CLAUDE.md`의 목표·배경을 구현으로 옮길 때 참고하는 세부 스펙 문서다. 화면 표시값, 상호작용,
배포 방식을 정리했다 — UI나 배포 관련 코드를 만질 때만 참조한다.

## 화면 표시

프로그램은 시작할 때 모니터 구성을 한 번만 감지해, 모니터마다 상단 중앙(위쪽 여백 2px)에
인디케이터 창을 하나씩 띄운다. 실행 중에 모니터 구성이 바뀌어도 반영하지 않으며, 반영하려면
재시작해야 한다.

인디케이터는 한 변이 26px인 정사각형이다. 이 값은 런타임 설정 파일이 아니라 빌드 시점 코드
상수로 관리한다.

배경은 완전 불투명하며, 한글 입력 모드는 빨강(`#FF0000`), 영문 입력 모드는 파랑(`#0000FF`)으로
표시한다. 글자는 흰색 굵게, 18pt 맑은 고딕으로 가운데 정렬하고, 한글 모드에는 "한", 영문
모드에는 "A"를 표시한다.

창은 항상 위(topmost)에 떠 있고 포커스를 가져가지 않으며(no-activate), 작업표시줄과 Alt-Tab
목록에는 나타나지 않는 tool window로 만든다. 상시 실행 프로그램이므로 리소스 사용량은 최소로
유지한다.

## 상호작용 (수동 교정 안전장치)

인디케이터를 클릭하면 API를 다시 조회하지 않고 현재 표시를 즉시 반전시킨다. TSF 이벤트를
놓쳤을 때를 위한 안전장치다.

모니터가 여러 대 떠 있으면 클릭 시 모든 인디케이터가 함께 반전된다. 인디케이터는 모니터마다
독립된 상태가 아니라 "현재 포커스 컨텍스트의 상태"라는 하나의 논리값을 복제해서 보여주는
것이므로, 일부만 반전되면 오히려 혼란을 키운다.

수동으로 교정한 뒤에도 실제 TSF 이벤트가 들어오면 정상적으로 새 상태를 반영한다.

교정 수단은 클릭만 지원한다. AHK 프로토타입에 있던 전역 단축키(`Ctrl+Alt+W`)는 의도적으로
두지 않는다 — 아래 "배포와 비기능 요구사항"에 있는 "새 전역 단축키를 점유하지 않는다"는
방침과 같은 이유다.

## 배포와 비기능 요구사항

시작프로그램 등록은 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`에 실행 파일 경로를
추가하는 방식으로 하며, 관리자 권한이 필요 없다. 등록 여부는 트레이 메뉴에서 토글한다.

WinForms UI EXE는 .NET 8 self-contained 단일 파일로 배포한다
(`dotnet publish -r win-x64 --self-contained -p:PublishSingleFile=true`). TIP 기반 접근을
유지한다면 TIP DLL의 COM/TSF 등록은 별도의 1회성 설치 단계이고, 이때는 관리자 권한이
필요하다 — HKCU만으로는 COM 등록 자체는 성공해도 TSF가 로드하지 않기 때문이다(ADR-0005
Update). 즉 설치 시 UAC 승인이 한 번 필요할 뿐, 평소 실행에는 관리자 권한이 필요 없다.

트레이 아이콘은 상태와 무관한 고정 아이콘을 쓴다(상태 표시는 인디케이터가 전담). 디자인은
`docs/assets/tray-icon-reference.png`를 참고하되 중앙 심볼만 "!"에서 "A"로 바꾼다. 우클릭
메뉴는 "시작프로그램 등록/해제"와 "종료" 두 항목으로 구성한다.

사용자가 이미 쓰고 있는 AutoHotkey 스크립트(ESC 입력 시 영문으로 강제 전환)와 충돌 없이
독립적으로 함께 실행되어야 하므로, 새 전역 단축키는 점유하지 않는 걸 권장한다.

값의 출처(AHK 프로토타입, 트레이 아이콘 디자인 이미지)는
[참고 자료](prototype-reference.md)에 따로 정리했다.
